# SI32 T0 — baseline pin

## Why a tracked duplicate of the harness pin exists

SI31's close-out (`plans/state-residual-fix-batch/README.md:216-236`)
records that its own T0 pinned `test-results/state-declared-size-baseline.jsonl`
(sha256 `e456ae76…`, summary `273/2660/2563/60/37/0/42`) — but every one of
SI31's six batch gates *re-pinned* that same gitignored path on success
(`cp /tmp/... test-results/state-declared-size-baseline.jsonl`). By the time
SI31 closed, T0's original file no longer existed anywhere on disk: it had
been overwritten six times and `test-results/*` is excluded by `.gitignore`
line 24, so git never held a copy either. SI31's close-out could not
byte-diff "mission start" against "mission end" — it had to reconstruct the
mission-wide delta by chaining the decision journal's per-batch summary
deltas arithmetically (`60 →(T2) 54 →(T3) 53 →(T4) 48 →(T5) 47 →(T6) 47`)
and cross-checking that chain against a fresh full measurement run.

SI32's T0 closes that gap: `tests/fixtures/si32-harness-baseline.jsonl` is a
byte-identical copy of the gitignored pin, but tracked (verified below), so
T4's close-out can `cmp` the tracked copy against the live pin directly
instead of reconstructing a chain.
