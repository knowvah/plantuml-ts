## Observation: a detached census worktree silently zeroes candidates unless gitignored asset dirs are linked
- **Context**: SI24 orchestrator + T6 both ran `shape-match-report.ts` / `dot-sync-report.ts` in a detached `git worktree` at a fixed commit (the SI23 method note: the census is invalid while a parallel agent has uncommitted work in the shared tree).
- **Finding**: the scripts import live modules and read gitignored inputs; a bare worktree lacks `node_modules`, `test-results/`, `oracle/dist/`, `assets/stdlib/`, `packages/*/assets`, `packages/*/generated`. Without `assets/stdlib` every candidate graph rendered empty and the report read as a mass regression. Symlinking those dirs from the repo into the worktree gives byte-identical baselines (verified: baseline at `9c4ed349` reproduced README's 783/26,206 and 699/266/257/89/78 exactly).
- **Impact**: recipe for a clean-tree census during parallel batches: `git worktree add --detach <dir> <sha>`; `ln -s` the six ignored paths; run the scripts from inside; diff per fixture (`grep -E '^[a-z]+/[a-z0-9-]+ '`) against the previous capture; `git worktree remove --force` after. Also: `dot-sync-report.ts` has no `description` type — use `component` and `usecase`.
- **Confidence**: High.
