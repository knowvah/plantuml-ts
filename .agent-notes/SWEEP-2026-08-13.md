# Notes sweep, 2026-08-13 — what was deleted and the evidence that retired it

Seven notes were **deleted**, each because its central claim is verifiably
false against the current tree. A note asserting a violation that no longer
exists is worse than no note: it sends the next reader to re-check something
already fixed. This file is the audit trail so the removals are not silent.

Fourteen further notes were **archived, not deleted**, to
`.agent-notes/archive/` — see that directory's README. Archived notes are
history, not errors.

The archive pass started at 28 and was cut to 14 by a check that should have
run first: **39 source comments cite notes by full path** (`.agent-notes/T10a-
separator-primitives.md`), so half the batch was live documentation wearing a
task-shaped title. Those 14 went back. The rule that survived is
reachability, not shape — a note cited from `src/`, `tests/`, `oracle/` or
`scripts/` stays at the top level.

## Later the same day: one more deleted, for the opposite reason

`description-invis-over-emission.md` recorded that we emit one `style=invis`
edge the jar does not, on four fixtures, and that it blocked the DOT gate from
comparing `style=invis` at all. **Fixed hours later, so the note was deleted on
the same rule as the seven above — its central claim is no longer true.**

The cause is worth stating here because it is the kind of thing that gets
re-introduced: upstream keeps `hidden` and `invis` as *separate fields*.
`-[hidden]-` routes through `WithLinkType#goHidden` (`WithLinkType.java:100
-102`), a DRAW-time flag; `style=invis` comes from `Link#isInvis()`
(`Link.java:177-182`), which reads a different field the bracket keyword never
touches. This port set `invis` from `hidden` and so emitted the attribute on
links the jar leaves alone. Removing that one line took description from
319 matching / 4 over to **323 matching / 0 over / 0 under**, and unblocked the
comparator: `style=invis` is now compared on all 166 fixtures that carry it,
verified by disabling emission and watching 156 tests fail.

The full mechanism lives in `description/link-edge-attrs.ts` next to the code,
which is why it is not duplicated as a standing note.

## Method

Claims were checked against the tree, not against memory or against each
other. One heuristic — flagging notes whose referenced `src/` paths had all
vanished — was **discarded as broken**: its `while read` loop ran in a
subshell, so the counters never propagated and every result was a false
positive. Every path it flagged as missing was present. Recorded here because
the failure mode is subtle and worth not repeating.
