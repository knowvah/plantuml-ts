## Observation: the quantifier/role arm's leading-`~` strip is CharHidder, not the visibility strip
- **Context**: SI24 T1 (`151b5317`), `class/focaci-80-suzu938` headlabel `~* initiators` 61 vs oracle 53.
- **Finding**: `Display#manageGuillemet(manageVisibilityModifier)` (`klimt/creole/Display.java:410-419`) has exactly one caller, `abel/LinkArg.java:71` — the MAIN label. Quantifiers (`SvekEdge.java:329-351`) never reach it. What removes the `~` is `CharHidder.hide` (`utils/CharHidder.java:59-90`), run on every creole line by `StripeSimple#analyzeAndAdd` (`klimt/creole/legacy/StripeSimple.java:150`): `~` followed by one of `_-"#][*./<` is a creole ESCAPE; the next char survives literally. Solo oracle renders: `+ initiators` 56, `# initiators` 62, `~initiators` 56 (all unstripped), `~*initiators` 53, bare `*initiators` 60 (creole list bullet). Ported as `stripLeadingEscapedChar` in `src/core/edge-label-box.ts` (leading position only; list-bullet path not ported).
- **Impact**: any "visibility strip" reasoning about quantifier/role labels is wrong for `+`/`-`/`#` prefixes; a mechanism that produces the right number on one fixture can still be the wrong mechanism — check the call graph, not the arithmetic.
- **Confidence**: High (Java read + oracle experiments).
