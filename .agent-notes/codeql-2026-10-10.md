- **Context**: Alert 24 (`js/html-constructed-from-input`, document-shell.ts).
- **Finding**: `renderSync` with `skinparam preserveAspectRatio x"onload="alert(1)`
  on an activity diagram emitted `preserveAspectRatio="x"onload="alert(1)"`. The
  activity renderer forwards the theme value verbatim and the shell concatenated

- **Impact**: Fixed by escaping at the shell (d5eca49f5). Alerts 26/27 on
  the same function (`style`, `width`) carry only numbers and an

- **Confidence**: High

## Observation: JS `\s` with the `u` flag is wider than the jar's `[%s]`
- **Context**: Rewriting `RE_HIDE_SHOW_BY_GENDER` (alert 25, exponential ReDoS).
- **Finding**: Upstream `[%s]` → `\s ` (Pattern2.java:57), and Java `\s` is
  ASCII-only. Ported regexes that use `\s` with `'u'` also accept U+2028/U+2029
  (and other Unicode spaces) as separators where the jar does not.
  `ReadLineReader` already splits `\r`/`\n` out of every line.
- **Impact**: A latent over-acceptance across every ported command regex;
  only reachable with Unicode separators in source. Not audited.
- **Confidence**: High for the mechanism; the breadth is unmeasured.

## Observation: upstream command regexes can be exponential
- **Context**: Alert 25.
- **Finding**: `CommandHideShowByGender.java:76` repeats a group whose
  alternatives overlap (keywords ⊂ `[%pLN_.]+`; `<<.*>>` spans tokens). V8
  took ~100 ms at 22 tokens, doubling per token. The port mirrors upstream
  regexes, so it inherits upstream's backtracking; CodeQL only sees literal
  patterns, not `RegexConcat`-built ones (see codeql-2026-09-19.md).
- **Impact**: A language-preserving rewrite is safe when the captures
  are unused. Prove it by brute force against the old pattern (8.2M inputs here).
- **Confidence**: High
