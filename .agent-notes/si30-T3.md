# SI30 T3 — core seams through `Sea`

## Observation: `buildLineAtoms('')` yields one blank text atom, not an empty list
- **Context**: Sea-layout guard for atom-free stripes in `creole-sea-line.ts`.
- **Finding**: `StripeSimple.ts#buildLineAtoms('')` returns a single `'text'`
  atom whose text is `' '` (one space). No caller of the lexer can therefore
  produce the empty-atom stripe `SheetBlock1.java:136-137` skips; the guard in
  `layoutLineThroughSea` is reachable only from a hand-built atom array.
- **Impact**: A blank creole line is MEASURED (height = the line font size,
  width 0 under the deterministic table), not skipped. Any future Sea seam
  must keep the guard anyway — `Sea#getHeight` throws on an empty sea
  (`Sea.java:120-126`) — but must not expect it to fire for `''`.
- **Confidence**: High (test-pinned, `leaf-sizing-sea-layout.test.ts`).

## Observation: upstream floors the atom DIMENSION but not the DRAW height
- **Context**: deriving per-run `dy` from `Sea` placements.
- **Finding**: `AtomText#calculateDimensionSlow` floors a run's height at 10px
  (`AtomText.java:178-179`) while `#drawU` reads the UNFLOORED
  `rect.getHeight()` (java:213). A run measuring under 10px therefore draws
  ABOVE where its own box bottom implies, by `10 - measuredHeight`.
- **Impact**: Any run below 10px — `<size:8>`, or a `<sup>` muted from the
  class default 12 down to 9 — carries that offset in `dy` even when it is
  `FontPosition.NORMAL`. Renderers reconstructing a baseline as
  `lineTop + lineHeight - size/4.5` must add `dy` to stay on upstream's
  baseline; ignoring it draws small text too low.
- **Confidence**: High (Java read; pinned in both T3 test files).
