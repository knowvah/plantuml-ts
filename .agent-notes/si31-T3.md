## Observation: `npx jiti scripts/measure-composite-declared-size.ts <a> <b> ...`
does not accept multiple slug args via a bash unquoted `for g in $VAR` loop
- **Context**: Re-measuring the nine guard fixtures individually before/after
  the G21 fix.
- **Finding**: `for g in $GUARDS` (an unquoted space-separated string
  variable) did NOT word-split in this session's bash tool — `for g in
  $GUARDS; do echo "[$g]"; done` printed the WHOLE string as one iteration
  instead of one per word (confirmed with a minimal repro; `IFS` looked
  normal). Passing all nine slugs as separate `npx jiti ...` argv entries in
  one invocation also collapsed to a single `"unmatched": true` row for the
  concatenated string. Using a bash ARRAY (`GUARDS_ARR=(...)`
  `for g in "${GUARDS_ARR[@]}"`) worked correctly, one arg per iteration.
- **Impact**: Any future task in this repo re-measuring multiple named
  fixtures with this harness should use a bash array, not a plain
  space-separated string variable, when iterating in this tool's shell.
- **Confidence**: High — directly reproduced twice (unquoted-var loop and
  direct multi-arg invocation both failed identically; array form fixed it).
