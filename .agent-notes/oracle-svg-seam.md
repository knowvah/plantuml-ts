## Observation: the 4 "non-deterministic" fixtures are deterministic-mode crash pages with a random icon
- **Context**: user asked to characterize the jitter (2026-10-08); 10 solo renders each, new oracle jar.
- **Finding (deltas)**: every run distinct (10/10 md5s per fixture). usecase kovaxi-11/zidebi-71: height fixed (1474 canvas, 1310 nested image), only the nested image width varies 743–802 px, canvas = image + 131. activity runima-82/pixisi-38: one small PNG varies (17x20 … 78x81) from a fixed pool — identical bitmaps (same md5) recur across both fixtures; the 255x255 / 183x183 images are stable.
- **Finding (source)**: the PNGs are PlantUML's `fun/spriteNNN.png` easter-egg icons (strawberry, Pac-Man, ghosts, bomb, invader, Apple logo, Mona Lisa, Eiffel tower, cat…). `IconLoader.getRandom()` (`fun/IconLoader.java:55-74`) `Collections.shuffle`s the 31 names with an unseeded Random; its only callers are the crash pages `crash/CrashImage.java:70` and `crash/GraphvizCrash.java:87`.
- **Finding (crash)**: all four crash with `IllegalArgumentException: start=X end=X` at `klimt/compress/Slot.java:44-45` (`start >= end`) from `SlotFinder.drawText` (`SlotFinder.java:127-133`), on a UText of a single space `" "` at 12pt, mode ON_X (instrumented scratch jar, not committed). activity: the whole diagram crashes; usecase: only the nested `{{ }}` diagram does.
- **Finding (why only here)**: upstream's own width table `UnicodeFontWidthSansSerif` block 0 gives U+0020 width 0 (index 32 = 0; `UnicodeBlock.getWidth`), so under `PLANTUML_DETERMINISTIC_TEXT` a lone space is zero-wide and `TextLimitFinder.drawText` (`TextLimitFinder.java:82-90`) yields minX == maxX. With real font metrics the same jar renders all four cleanly (rc=0, no crash). Our `WidthTableMeasurer` ports the same table: `measure(" ")` = 0, `"a b"` = 2 x `"a"`.
- **Impact**: these four caches are crash pages of the measurement mode, not targets; seeding the shuffle would make them stable but still crash pages. Exclude from equality; decide separately whether to compare them against a real-metrics render.
- **Confidence**: High (repeated renders, instrumented jar, stock-metrics control).
