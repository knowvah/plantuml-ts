## Per-mechanism detail

### M1 — bullet-list activities (12): `CommandActivityList`

Exemplar `bokupo-95-rede308` (`*A`/`*B`): `parseActivity()` refuses at
line 0 (`*A`), `kind=syntax`, `consumed=0`. Upstream's
`CommandActivityList` (`ActivityDiagramFactory3.java:160`) matches
`^[-*]` + optional space + a lazy `LABEL` running to end-of-line — for a
single-level line (`* A`, `- A`, `*A`, `-A`) this yields a clean label
with no residual marker, so a straightforward port (regex match, strip
the leading `[-*]\s?`, add an activity node) suffices. **Size ≈25 NLOC**
(comparable to `trySimpleKeyword`, 17 lines).

4 of the 12 (`activity-legacy1-example-4`, `-5`, `cemilu-33-voma521`,
`rizoba-79-feco788`) are **nested** (`** B`, `*** C`). Hand-tracing
`CommandActivityList`'s regex shows the SECOND star is NOT consumed by
the command itself — it lands inside `LABEL` as literal text (`"* a1"`)
— but the jar's golden for `rizoba` renders clean `"a1"`/`"a11"` text
preceded by an `<ellipse>` (depth 2) / `<rect>` (depth 3) bullet glyph.
That nesting-with-glyph behavior is **Creole's own `LIST_WITHOUT_NUMBER`
bullet-list rendering**, not `CommandActivityList` — and this port has
**already documented that as unported, in a different mission**:
`src/core/klimt/creole/legacy/CreoleStripeSimpleParser.ts`'s header
("FULL-mode-only `*`/`#` bullet-list patterns — not ported") and
`src/core/klimt/creole/StripeStyleType.ts`'s doc comment (`LIST_WITHOUT_
NUMBER`/`LIST_WITH_NUMBER` are named for fidelity but never produced).
Per D3, porting `CommandActivityList` alone still ROUTES all 12 to
`activity` (the parse succeeds, `data-diagram-type` becomes ACTIVITY) —
the 4 nested ones just render a literal `"* a1"`-shaped label instead of
a bulleted one, a **pre-existing, already-filed rendering gap**, not a
new defect this row creates.
