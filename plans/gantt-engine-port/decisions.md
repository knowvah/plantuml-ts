## D1 — layout and names

`src/diagrams/gantt/{,command,core,data,draw,draw/header,lang,ngm,ngm/math,
solver,time,timescale,ulang}/<UpstreamName>.ts`, each carrying `@see` to its
Java origin. `Failable` already lives at `src/core/gantt/Failable.ts` (used
across engines) and stays there; gantt imports it. `I18nTimeData` sits in
upstream `utils/` (generated by `I18nTimeDataGenerator`, not ported), so it
lives in `src/core/utils/`. Rejected: collapsing modules (CLAUDE.md: preserve
upstream names; do not refactor while porting).

## D2 — the `java.time` subset

`TimePoint` wraps a UTC `LocalDateTime` (`time/TimePoint.java:55`); gantt also
uses `LocalDate`, `DayOfWeek`, `Month`, `YearMonth`, `WeekFields`,
`Duration`. Port exactly the methods gantt calls, as epoch-day / second-of-day
integers over the proleptic Gregorian calendar, UTC only, in
`src/core/time/<JavaName>.ts`. Deterministic, no host-timezone traps, and the
shared date module timing diagrams need later (mission-index SI2). Rejected:
JS `Date` (timezone traps, no `WeekFields`/`YearMonth`).

## D3 — the clock (user design, 2026-10-24)

Upstream reads the wall clock: `TimePoint.todayAtMidnight()` →
`LocalDate.now()` (`time/TimePoint.java:93-95`, JVM default zone),
`TimePoint.nowUtc1()` (`:88-90`), `Instant.today()` (`time/Instant.java:49-51`);
`GanttDiagram.java:456-466` uses it when `today` has no date. TIM `%now`/
`%date` read `TimEnvironment.clock` (`src/core/tim/builtin/TimEnvironment.ts:
33,121`, default 0).

- **D3a library:** `src/core/clock.ts` exports the seam (`nowMillis()`, plus
  the zone used for "local date"); `TimEnvironment.clock` and gantt both read
  it. Default `nowMillis = 0`, zone UTC — byte-identical to today's `%now`.
  The only setter is an internal option on `InternalRenderOptions`
  (`src/core/internal-render-options.ts`, NOT re-exported; no public
  `RenderOptions` field; `.d.ts` unchanged — stop 6).
- **D3b harness:** `oracle/capture-clock.json` maps each clock-dependent slug
  to `{ epochMillis, zone }`. Backfill: `gantt/lituri-55-caju105` and the
  `unknown` `%date` row from their `in.svg` mtime (zone America/Chicago).
  `scripts/oracle-render.sh` and `scripts/oracle-corpus.ts` record the entry
  at capture for clock-dependent sources (`today` without a date, `%now`,
  `%date` without a fixed argument). Every conformance renderer that passes
  `jarCompatibleStyleInput` also passes the slug's recorded clock.
- **D3c gate:** a test fails when a clock-dependent source has no record.
- **Recorded fallback (user, 2026-10-24):** if capture-and-compare proves
  flaky (stop 12), add an oracle-fork seam (`-DPLANTUML_FIXED_NOW`) and
  re-capture instead. Not built unless needed.

## D4 — rendering path

`GanttDiagram extends TitledDiagram` (`GanttDiagram.java:107`) and exports a
`TextBlock` (`:184 getTextBlock`). Draw through klimt `UGraphicSvg` with
`basicSvgOption({...})`, then the document shell, setting `diagramType:
'GANTT'` (the jar writes `data-diagram-type="GANTT"`). Styles come from the
`ganttDiagram` style tree (already in the built-in skins). `lengthAdjust`:
`getSkinParam().getlengthAdjust()` → `lengthAdjustOverride` on the option AND
`fragment.lengthAdjust` (lad D1/D3). Notes reuse the ported `Opale`
(`draw/AbstractTaskDraw.java:68`).

## D5 — `long` maths

`ngm/math/Fraction.java:66-67` holds `long` num/den with no `*Exact` calls
(silent wrap). Port as `number`; document each long-math site; a unit test
shows realistic gantt values (multi-year spans in seconds × allocations) stay
below `Number.MAX_SAFE_INTEGER`. Rejected: `BigInt` (slower, spreads; no
plausible input reaches 2^53).

## D6 — build order

File-level SCC layering of upstream (`diagnosis/upstream-scc-layers.txt`):
L00–L01 → batch 2, L02–L05 → 3, L06–L09 → 4, the single 25-file cycle (L10) →
batch 5 as one serial chain in one worktree, L11 → 6, L12–L16 → 7. Same-batch
tasks never depend on each other (`diagnosis/upstream-batch-groups.txt`). The
batch-5 chain commits per task but may not typecheck until its last task;
gates run at the chain's end. Rejected: a vertical slice first (leaves
half-ported classes).

## Amendment 1 (2026-10-24, batch-1 close) — the grammar needs `com.plantuml.ubrex` (APPROVED by the user 2026-10-26: "approve D11")

**Finding (orchestrator, before launching batch 2).** 47 of the 167 gantt files
import `com.plantuml.ubrex` (Unicode Bracketed Expressions): every `lang/Subject*`
and `lang/Complement*`, `lang/{Words,Verbs,Something,PairOfSomething,DayPattern,
TimeResolution}`, `time/{MonthUtils,DayOfWeekUtils}`, `ulang/*`,
`command/{NaturalGanttCommand,CommandHideShowColumns,CommandPrintBetween}`,
`GanttTaskTableColumn`. The grammar is built by composing `UBrexPart` trees
(`UBrexConcat`/`UBrexOr`/`UBrexNamed`/`UBrexLeaf("「dDtTeE」")`…) and read back
through `UMatcher.findFirstValueByKey` (`lang/SubjectDayAsDate.java:107-142`).
The library — `~/git/plantuml/src/main/java/com/plantuml/ubrex/` (43 files incl.
`builder/`, 3,380 lines) plus `command/UBrexSingleLineCommand2.java` (196) and
`url/UbrexUrlBuilder.java` (220) — has **no port in `src/`** (`find src -ipath
'*ubrex*'` empty). The SCC layering in `diagnosis/upstream-scc-layers.txt` was
computed over `gantt/` only, so this edge is outside every batch; D6's "everything
these files reference is in batch 1 … or this task" is false for T2b (`TimeResolution`,
`MonthUtils`, `DayOfWeekUtils`), T2d (`Words`, `Verbs`, `Something`, `ulang/*`),
T3c (`DayPattern`, `PairOfSomething`) and all of batches 6–7. Precedent: E2r ported
creole's observable semantics without the ubrex DSL (`planning/mission-index.md`
E2 row) — viable there because creole's commands are leaves; gantt's
subject/verb/complement grammar IS ubrex composition. ubrex's own outside imports
are already ported or trivial (`StringLocated`, `LineLocation`, `BlocLines`,
`RegexResult`, `PSystemError`, `NoSuchColorException`; `TeaVM`/`Explain` are
annotations).

**Proposal (orchestrator recommendation — needs the user's ruling):**
- **D11 (new) — port ubrex first.** New **batch 1b**: mirror
  `com/plantuml/ubrex/**` file-for-file to `src/core/ubrex/**` (upstream names,
  D1-style `@see`), plus `UBrexSingleLineCommand2` → `src/core/command/` and
  `UbrexUrlBuilder` → beside the existing url code; layered by its own SCC order
  (≈3 parallel tasks + close, same contract). Batches 2–7 then proceed unchanged
  except T2b/T2d/T3c/6/7 read-sets gain `src/core/ubrex`. Existing engines are
  NOT migrated onto it (separate mission; no movers expected).
- Rejected alternative: translate each gantt `UBrexPart` tree to a JS `RegExp`
  per file — a structural divergence in the parser seam (CLAUDE.md: "a
  structural divergence IS the bug"), and `findFirstValueByKey` over repeated
  named groups has no `RegExp` equivalent.
- Cost: ≈ +3.8k Java lines (mission was 20.1k), one extra batch.

**As approved, refined at planning (2026-10-26, orchestrator):**
- Placement: `com/plantuml/ubrex/**` → `src/core/ubrex/**` (`builder/` kept);
  `regex/RegexResult.java` + `regex/RegexPartialMatch.java` → `src/core/regex/`
  (RegexResult has a `UMatcher` constructor, `RegexResult.java:58`; every gantt
  command's `executeArg` takes one); `command/CommandControl.java` +
  `command/UBrexSingleLineCommand2.java` → `src/core/command/`;
  `url/UbrexUrlBuilder.java` → `src/core/url/`.
- `UBrexSingleLineCommand2` keeps its members and per-line semantics but takes
  the single `StringLocated` line where Java takes `BlocLines` — the adaptation
  `src/core/command/Command.ts` already documents for every ported engine (no
  generic `BlocLines` class exists in `src/`). Used by gantt
  `CommandHideShowColumns` (T6b), `NaturalGanttCommand` and
  `CommandPrintBetween` (T7a).
- Build order: ubrex's core is one cycle (`Challenge`↔`ChallengeResult`↔
  `Capture`↔`TextNavigator`, `AtomicParser`↔`CompositeList`), so batch 1b is a
  serial chain T1d→T1e→T1f in ONE worktree (the D6 batch-5 pattern), each task a
  fresh agent reading the previous commits. Upstream's 28 ubrex tests
  (`src/test/java/com/plantuml/ubrex/`) are ported as the conformance oracle.
- Existing engines are not migrated onto ubrex; batch 1b's close expects 0
  movers in all 28 engines.
