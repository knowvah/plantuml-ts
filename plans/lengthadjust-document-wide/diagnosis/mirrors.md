## Paragraphs: rows that do not survive

**Chromed description (`src/index.ts:200` / `description/index.ts:155`, owner T2b).** `unwrapKlimtSvg` re-reads the klimt SVG string and builds a new
`RenderFragment` literal (`description/renderer.ts:354`) containing only
`body, width, height, background, diagramType` (plus `extraDefs`,
`documentBackgroundRect` at `:355-356`). The root `lengthAdjust` attribute the
klimt option wrote is discarded by `extractFlatContent`, so a field set only on
the option cannot reach the shell. Change: `description/index.ts`, insert after
`:155` `...unwrapKlimtSvg(svg, theme.colors.background),` the spread
`...(theme.lengthAdjust !== undefined ? { lengthAdjust: theme.lengthAdjust } : {}),`.
(`unwrapKlimtSvg` takes no theme, so the spread belongs at the caller; this keeps
`index.ts:200` untouched.)

**board / files / packetdiag / chart (owners T1a then T2f).** The fragment has no
`diagramType`, so `assemble-svg.ts:354-361` takes `svgRoot(formatted.width,
formatted.height, [formatted.body], formatted.background, formatted.extraDefs)`;
no argument carries `lengthAdjust`. D2's route (`diagramType` + a
`finalizeShellFragment` arm) is the only change; `svgRoot` is untouched.

**json / yaml / hcl (owner T1d)** do not DROP the field; they never SET it: the
single line is `src/diagrams/json/renderer.ts:445-449`.

No harness mirror drops the field: `render-fixture-class.ts`,
`render-fixture-activity.ts`, `render-fixture-sequence.ts` need no D6 edit.
No klimt `UGraphicSvg` is on the json path.
