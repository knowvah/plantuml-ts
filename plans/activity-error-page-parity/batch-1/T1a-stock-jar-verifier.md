# T1a — stock-jar verifier + record (D5)

## Context
The error-page rule (decisions.md) only applies where the **stock** jar
errors. The oracle jar carries four seams (`oracle/pin.json#patches`); an
error that only the patched jar produces is a seam artifact and must not earn
the looser verdict. At planning, stock upstream at `97a5992` was built from
`git -C ~/git/plantuml archive 97a5992… | tar -x` with
`./gradlew jar -x test -x generateGitProperties` (the git-properties task
needs `.git`; skipping it does not change the source), seam strings
`PLANTUML_DETERMINISTIC_TEXT`/`PLANTUML_DUMP_DOT` absent from the jar, and all
14 activity error fixtures gave the oracle's message and line.

## Task
1. `scripts/stock-jar-verify.sh`: read `upstreamSha` from `oracle/pin.json`;
   if `oracle/dist/stock/plantuml-stock-<sha>.jar` is absent, `git archive`
   that SHA from `~/git/plantuml` into a `mktemp -d` dir and build it as
   above. **Never** `git switch`/`checkout` the fork (memory:
   oracle-jar-fallback-path). Verify the seam strings are absent; fail if not.
2. Select inputs: every `test-results/dot-cache/<bucket>/<slug>/in.svg` that
   is an oracle error page (a cheap pre-filter is fine here — it only picks
   candidates; the verdict comes from step 3).
3. For each, run the stock jar on `in.puml` with **no** `-D` flags, one JVM
   per fixture, `-Djava.awt.headless=true` only. Decide "stock errors" from
   upstream's own signal — read and quote `cli/ExitStatus.java:43,104`
   (exit 200) and/or `--check-syntax` (`cli/CliFlag.java:138-139`) and the
   code that sets them. Capture message + line (from `--check-syntax` output
   or the stock SVG's error text — choose, quote, journal via the report).
4. Write `oracle/goldens/stock-error-pages.json`:
   `{ upstreamSha, plantumlVersion, errors: { "<bucket>/<slug>": { line, message } } }`,
   keys sorted, no timestamps (deterministic). List oracle-error fixtures the
   stock jar DRAWS separately in the report (stop 9 — do not write them).
5. `tests/oracle/svg-conformance/stock-error-pages.test.ts`: shape check;
   `upstreamSha === pin.json.upstreamSha` else fail naming
   `scripts/stock-jar-verify.sh`; the 14 activity slugs from `fixtures.md`
   (ERR/REFUSE rows) present with their planning messages.

## Write-set
`scripts/stock-jar-verify.sh`, `scripts/lib/stock-jar-*.ts` (optional),
`oracle/goldens/stock-error-pages.json` (generated by the script — the one
golden this task may write), `tests/oracle/svg-conformance/stock-error-pages.test.ts`,
`.gitignore` (only if `oracle/dist/stock/` is not already ignored).

## Read-set
`oracle/pin.json`; `oracle/build-oracle.sh:30-50`; `scripts/oracle-render.sh`;
`~/git/plantuml/src/main/java/net/sourceforge/plantuml/cli/ExitStatus.java`;
`.../cli/CliFlag.java:130-145`; `.../Run.java` (where the exit status is set).

## Interface (consumed by T2a)
`oracle/goldens/stock-error-pages.json` —
`{ upstreamSha: string; plantumlVersion: string; errors: Record<string /* "<bucket>/<slug>" */, { line: number | null; message: string }> }`.
Only fixtures the stock jar errors on appear.

## Acceptance
- Given pin `97a5992`, when the script runs, then the record lists the 14
  activity error fixtures with the messages/lines in `fixtures.md`.
- Given a record whose SHA ≠ `pin.json#upstreamSha`, when the test runs, then
  it fails and names `scripts/stock-jar-verify.sh`.
- Given the script re-runs with no pin change, then the record is byte-identical.

## Observability
N/A — dev-time tool; the report lists counts per bucket and every stock-draws
fixture.

## Rollback
Reversible (revert; the cached stock jar is gitignored).
