# T6 — `scripts/parity-dashboard.ts` + drift test

## Context
plantuml-ts ports PlantUML; the jar is the oracle. Per-type measurement
artifacts already exist as committed JSON (list below), but no document
composes them, so the published `docs/parity-report.md` (DOT parity only,
five types with numbers, 23 rows "not yet measured") has been stale since
2026-07-18. `docs-site/copy-reports.mjs` mirrors that file to
plantuml.knowvah.com/parity at build time; keep the path. Scripts run via
`jiti`; tests are vitest under `tests/unit/scripts/`. Prettier runs on
staged files at commit.

## Task
Write `scripts/parity-dashboard.ts` (`npm run parity:dashboard`) that
reads ONLY the artifacts below and writes `docs/parity-report.md`:

Sources (all relative to repo root):
- Rows: `tests/visual/data/*.json` — one row per file, alphabetical;
  corpus count = array length.
- Engine: the registry in `src/index.ts:96-109` (14 plugins). Map manifest
  bucket → plugin type: `component|usecase|c4 → description`,
  `packet → packetdiag`, else same name. Buckets with no plugin →
  `no engine (Dn todo)` using the D-row ids in
  `planning/mission-index.md:150-165` (timing D1, mindmap D2, wbs D3,
  gantt D4, network D5, gitgraph D6, salt D7, ditaa D8, chen D9, ebnf D10,
  regex D11, wire D12, c4 D15). `unknown` → `accounting bucket`.
- Oracle cache: `test-results/dot-cache/<type>/` dir count of `.done`.
  Absent → `no oracle captured`.
- DOT parity: `dotParityRows(jar)` from `scripts/dot-parity-rows.ts` (T4).
  Its `note` is the reason string when `comparable === 0`.
- Survey (production `renderSync` path): `tests/oracle/svg-conformance/
  parity-<type>.json` (T3) — counts per verdict, `dotEqual` count,
  `generatedAt`. Missing file → `no survey yet`.
- Census (low-level helper path): `tests/oracle/svg-conformance/
  census-<type>.json` (T2) — `bucket === '0'` count over `status==='ok'`,
  `generatedAt`. Missing → `no census yet`.
- Byte-exact ratchet pins: `oracle/goldens/svg-<family>/ratchet.json`
  `fixtures.length`; family mapping `component|usecase → svg-description`
  (filter by `type` field), `class → svg-class`, etc. Missing →
  `no ratchet yet`.
- Diff-baseline: `oracle/goldens/svg-<family>/diff-baseline.json` —
  count by `status`, sum `weightedScore` over `baseline`, max
  `measuredAt`. Only sequence, activity, description have one.
- Routing: `oracle/goldens/svg-conformance/routing-baseline.json`
  `fixtures[]` grouped by `type` (cache dir) → `agree` /
  `known-misroute` / `jar-error` counts.
- Refusal: `refusal-baseline.json` grouped by `type` → `ok` / `known-gap`.

Document shape (front-loaded, ≤ 300 lines of output):
1. Generated banner (`<!-- GENERATED by scripts/parity-dashboard.ts — do
   not edit by hand -->`) and a two-paragraph preamble: what each column
   measures, and that survey and census differ by render path, not
   measurer (`decisions.md#d3`).
2. **Matrix**: `| type | engine | corpus | oracle | DOT equal | survey
   conformant / structural / diverged | census 0-diff | ratchet pins |
   diff-baseline (n · ΣweightedScore) | routing agree | refusal ok |`.
   Every empty cell is `n/a (<reason>)` from `decisions.md#d8`.
3. **Freshness**: per type, the `measuredAt`/`generatedAt` of each source
   it used (a table, one row per type).
4. **DOT parity** section: `dotParityMarkdown(rows, date)` from T4, verbatim.
5. Footnote: upstream `DiagramType` members with neither bucket nor
   engine (`decisions.md#d7` list).
No `Date.now()` anywhere: every date comes from an artifact; the banner
carries the newest `generatedAt` among inputs.

Pure core: `buildMatrix(inputs): MatrixRow[]` and `renderReport(model):
string` exported; IO in a thin `loadInputs()`. Tests exercise the pure
functions with synthetic inputs AND one drift test (D9):
`renderReport(loadInputs())` equals `readFileSync('docs/parity-report.md')`.

Also: `package.json` script `"parity:dashboard": "jiti
scripts/parity-dashboard.ts"`. Run it once and commit the regenerated
`docs/parity-report.md` (from whatever JSON is on disk at that moment; T7
refreshes). Links in the report to files not on the docs site use
absolute GitHub URLs (`https://github.com/knowvah/plantuml-ts/blob/main/…`)
so `copy-reports.mjs` needs no new rewrite rule.

## Acceptance criteria
1. Given the 28 manifest buckets, when built, then the matrix has 28
   rows, alphabetical, plus the footnote listing exactly the D7 members.
2. Given a cell with no artifact, when rendered, then it matches
   `/^n\/a \((no engine \(D\d+ todo\)|no DOT stage \(non-svek\)|no oracle captured|no ratchet yet|no survey yet|no census yet|engine, unclassifiable corpus|accounting bucket)\)$/`;
   a bare `n/a` never appears.
3. Given every numeric cell, when rendered, then the freshness table has
   that type's source date.
4. Given the committed `docs/parity-report.md`, when the drift test
   rebuilds from disk, then the strings are byte-equal (run twice to
   prove determinism).
5. Given `sequence`, when rendered, then DOT equal is `n/a (no DOT stage
   (non-svek))`, ratchet pins is `0`, and diff-baseline shows
   `1124 · <sum>` (the count from the committed file, not hardcoded).
